# V10.14 Phase 2：计划数据迁移专项验收

## 目标

将旧版计划模块中的「工作」分类移除，并把相关记录迁移到系统固定分类「未分类」。不修改记录的标题、备注、日期、状态、星级、提醒、创建／更新时间、完成信息及记录顺序。

## 迁移范围

- 普通计划：`state.plans` 中 `category === '工作'` 的记录。
- 已归档计划：归档记录仍位于 `state.plans`，因此与普通记录使用相同规则。
- 回收站：`state.trash[].plan` 中分类为「工作」的记录。
- 分类列表：移除「工作」，并将「未分类」追加到原有分类顺序末尾（若尚不存在）。

## 安全策略

1. 迁移函数先深拷贝输入状态，不直接修改原对象。
2. 只调整分类列表及上述记录的 `category` 字段。
3. 如果已完成迁移，再次执行应返回 `changed: false`，不重复写入。
4. 只有 LocalStorage 保存成功后，才替换当前内存状态和模块缓存。
5. 保存失败时保留原状态，并显示错误提示；再次进入计划模块时可重新尝试。
6. 不读取或写入工作、外语学习、整理模块的数据键。

## 自动回归测试

执行：

```bash
node scripts/test-plan-migration.mjs
node scripts/validate-v10.14.mjs
```

回归测试直接从 `index.html` 提取生产迁移函数，覆盖：

- 普通计划迁移。
- 已归档计划迁移。
- 回收站记录迁移。
- 原计划分类顺序保留及「未分类」追加。
- 非目标记录字段、完成数据、Trash 元数据及记录顺序保持不变。
- 原始输入对象不被修改。
- 重复执行的幂等性。
- 已迁移数据不发生额外变更。
- 缺少「未分类」时补齐固定分类。

静态契约检查另行确认迁移只在计划模块运行，且保存成功后才替换状态。浏览器 LocalStorage 配额不足／写入失败、真实用户数据迁移和 PWA 更新仍需实际浏览器验收，不能由 Node 回归测试代替。

## 用户更新建议

- 更新前，建议在「计划」模块导出 JSON 备份。
- 发布后打开「计划」模块，迁移会自动执行；无需手动点击迁移按钮。
- 不要清除浏览器站点数据来刷新版本。
- 如本地计划数据迁移完成后需要同步云端，请在计划模块单独执行一次云端上传。
