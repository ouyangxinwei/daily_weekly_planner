# 个人公司网站开发文档

本目录维护「慢慢计划」内个人公司网站模块的需求、架构决定、实施记录和验收结果。跨语言的客户、项目和跟进业务语义以[产品功能与业务规范](../product-specification.md)为总基线；本目录保留公司子系统的技术设计和阶段证据。

## 当前状态

- 当前应用版本基线：V10.45.0。
- 项目定位：个人开发练习优先，先实现可用版本，保持结构简单、易修改。
- 业务数据：使用主要业务表 `company_records`，不同记录类型共用基础字段，差异字段放入 JSONB。
- 认证：沿用慢慢计划现有自定义账号认证；Edge Function 在服务端再次验证请求身份。
- API：当前生产环境 `company-api` 为 v5；阶段 1-H 增加项目进度模式与 API 参数校验，数据库通过触发器同步自动进度。
- 阶段 1-A：设计基线已完成。
- 阶段 1-B：数据库迁移已应用，表、权限、错误密码及基础 CRUD/约束完成最小验证。
- 阶段 1-C：Edge Function 已部署 v3。
- 阶段 1-D：客户管理前端已完成并部署；用户已反馈真实浏览器 CRUD 测试 OK。
- 阶段 1-E：项目管理与业务跟进代码已通过 PR #32 合并至 main；用户已确认项目管理基础功能可用。
- 阶段 1-F：项目详情与手动进度管理（0–100%）已在 V10.43.0 合并、部署，用户已确认真实浏览器验证 OK。
- 阶段 1-G：项目任务管理（V10.44.0）已合并、部署，用户已确认真实浏览器验收通过；支持任务 CRUD、项目关联、状态和截止日期。
- 阶段 1-H：项目任务与进度联动（V10.45.0）已合并、部署并通过用户真实浏览器验收；自动进度按已完成任务比例计算，同时保留独立手动进度值。
- 下一阶段：根据实际业务使用情况评估阶段 1-I 的需求，不预先扩展未确认的业务范围。

## 维护规则

1. 每个阶段的关键决定、实施步骤和验收结果以 Markdown 记录。
2. 重要架构调整记录原因、影响范围和迁移方式。
3. 只做与当前阶段相称的必要测试，但不能省略关键安全检查。
4. 仅文档变更不提升应用 `VERSION`；只有实际应用功能发布时才更新应用版本及对应变更记录。
5. 数据库迁移、Edge Function 和 Storage 变更必须记录 SQL、配置、部署状态及验证结果。
