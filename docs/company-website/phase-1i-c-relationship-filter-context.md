# 阶段 1-I-C：关联筛选状态提示与快捷清除

- 应用版本：V10.48.0
- 开发分支：`feat/company-filter-context-1i-c`
- 基线分支：`main`（V10.47.0）
- 数据库：沿用 `public.company_records`
- API：沿用生产 `company-api` v5

## 1. 发现的问题

阶段 1-I-A 已建立跨模块导航，阶段 1-I-B 已增加关联信息预览，但从客户或项目进入关联列表后，筛选条件只在内部状态中生效，界面没有说明当前列表为什么只显示部分记录，也没有统一的清除入口。

## 2. 本阶段实现

- 项目列表按客户筛选时，显示当前客户上下文。
- 任务列表按项目筛选时，显示当前项目上下文。
- 跟进列表按客户或项目筛选时，显示对应上下文。
- 提供「清除关联筛选」操作，清除当前页面的关联条件并返回完整列表。
- 用户在跟进列表主动更改项目筛选时，自动清除之前的客户筛选，避免两个条件互相造成误解。
- 保留原有搜索、状态筛选、分页、CRUD 和跨模块跳转。
- 提供中英日文案及响应式样式。

## 3. 数据与兼容性边界

- 不新增或修改数据库表、字段、索引、迁移和 RLS。
- 不修改 Edge Function；继续使用生产 `company-api` v5。
- 不修改账号认证、业务记录结构、项目进度联动或云同步。
- 不写入或批量修改生产业务数据。

### 用户浏览器验收

刷新 Pages 页面并进入「个人公司网站」，重点检查：

1. 从客户卡片点击「查看项目」，项目列表上方是否显示当前客户，并且只显示该客户的项目。
2. 点击「清除关联筛选」，是否恢复完整项目列表。
3. 从项目详情进入任务列表，是否显示当前项目上下文；清除后是否恢复完整任务列表。
4. 从项目详情进入跟进列表，是否显示当前项目上下文；清除后是否恢复完整跟进列表。
5. 从客户进入跟进列表时，是否显示客户上下文；切换跟进项目筛选后，客户筛选是否自动解除。
6. 中、英、日文案及窄屏布局是否正常。
