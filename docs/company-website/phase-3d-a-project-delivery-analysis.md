# Phase 3-D-A：项目计划进度与实际进度偏差分析（V10.66.0）

## 1. 目标

在公司业务工作区增加独立的「项目交付分析」视图，将项目当前实际进度与根据项目开始日期、预计完成日期估算的日历计划进度进行比较，帮助快速识别落后和超期项目。

## 2. 数据来源与边界

只读取现有项目记录：
- `start_date`：计划开始日期。
- `due_date`：预计完成日期。
- `data.progress_percent`：当前实际进度，沿用手动/自动进度模式已维护的显示值。
- `status`：项目状态。

复用现有 `loadRecords('project')` 完整分页和短时缓存。分析只在浏览器端执行，不写回项目记录。

**本阶段不新增数据库字段/表，不修改 Supabase、RLS、Edge Function、company-api、认证或生产业务数据。**

## 3. 计划进度算法

计划进度按日历时间线性估算：

`plannedProgress = round((today - start_date) / (due_date - start_date) * 100)`

结果限制在 0%–100%。具体边界：
- 今天早于开始日期：0%。
- 今天等于开始日期：0%（若计划起止为同一天，则当天为 100%）。
- 今天位于开始与预计完成日期之间：按经过的日历天数线性计算。
- 今天等于预计完成日期：100%。
- 今天晚于预计完成日期：计划进度保持 100%，并单独标记「已超期」。
- 同日计划：计划日期当天及之后为 100%，之前为 0%。

实际进度复用 `data.progress_percent`，缺失按 0%，并限制在 0%–100%。偏差为：

`variance = actualProgress - plannedProgress`

偏差单位是百分点（pp），不是相对百分比。

该算法是当前时点的日历时间估算，不是历史保存的计划基线，也不代表任务实际工作量。

## 4. 状态与数据质量规则

- `cancelled` 项目完全排除。
- `completed` 项目保留在项目总数和列表中，但不计入进度落后/超期风险。
- `planned`、`active`、`on_hold` 等未完成项目按日期比较。
- 缺少开始日期或预计完成日期：标记计划日期不完整，不计算偏差。
- 日期格式或日历日期无效：标记日期无效，不计算偏差。
- 开始日期晚于预计完成日期：标记日期配置错误，不计算偏差。
- 日期问题项目单独计入「日期待补充」KPI，不当作正常或 0% 进度。

## 5. 初始风险分级

| 偏差（实际 - 计划） | 判断 |
|---|---|
| >= 0 pp | 符合计划 / 超前 |
| -1 至 -10 pp | 轻度偏差 |
| -11 至 -25 pp | 需要关注 |
| < -25 pp | 高风险 |

阈值为可调整的初始产品规则，不是行业标准。超期是独立标记，因此一个项目可以同时属于进度落后和已超期。
