# 阶段 2-C：项目与客户业务概况

## 1. 目标

在个人公司网站工作区增加独立的「项目与客户概况」入口，将项目状态、项目进度、任务完成情况、客户项目组合和近期业务活动集中呈现。该页面用于回答“目前项目组合处于什么状态、项目推进如何、哪些客户有业务往来、最近发生了什么”。

本阶段侧重当前业务结构和项目组合概览，不扩展为周/月趋势分析（该范围属于 2-D）。

## 2. 页面内容

### 项目概况
- 项目总数。
- 项目状态分布：计划中、进行中、暂缓、已完成、已取消；点击状态计数进入对应项目列表筛选。
- 平均项目进度：对非取消项目的 progress_percent 求平均并四舍五入；无可统计项目时为 0%。
- 已完成项目数、逾期项目数；逾期定义为预计完成日期早于浏览器本地今天，且状态不是 completed/cancelled。
- 项目进度列表最多显示 8 项，按最近更新时间优先；每项显示项目、所属客户、状态、进度及任务完成数/任务总数，点击打开现有项目详情。

### 客户项目组合
- 客户总数、已有项目的客户数。
- 客户列表最多显示 8 项，按关联项目数降序、最近业务活动时间降序排列。
- 每项显示客户名称、项目总数、进行中项目数和关联跟进数；点击打开现有客户记录入口。
- 项目归属沿用 project.parent_record_id；跟进客户归属优先使用 data.customer_id，其次 related_record_ids、父记录关系及项目所属客户。

### 任务与近期活动
- 显示全部任务总数及已完成任务数。
- 近期业务活动按项目、任务、跟进的更新时间/创建时间/业务记录时间排序，最多显示 8 项。
- 点击活动条目打开现有项目详情或任务/跟进编辑窗口。
- 不在本阶段加入周/月趋势图、转化率或预测指标，避免与 2-D 重复。

## 3. 数据口径与完整性

- 使用 company-api v5 的 GET /records 分页接口读取 customer、project、task、follow_up。
- 每页 limit=100；根据接口 total 连续读取，并校验分页 total 一致、页面未提前结束、最终数量等于 total。
- 不以当前列表第一页或前端分页缓存计算全局统计。
- 平均进度排除 cancelled 项目；项目状态分布仍包含全部五种状态。
- 项目任务完成数按 task.parent_record_id 对应 project ID 统计，status=completed 为完成，其余为未完成。
- 近期活动排序字段优先级：updated_at、created_at、record_date。
- API 失败或分页不完整时显示错误并清空概况内容，不将错误伪装成空数据或 0。

## 4. 交互与兼容

- 新增独立导航入口「项目与客户概况」，不挤占 2-A 业务总览与 2-B 待办中心。
- 项目状态、KPI、项目条目、客户条目及近期活动均可跳转到现有模块/记录。
- 简体中文、English、日本語；支持桌面与移动端。
- 切换界面语言后更新导航和本页面文案。
- 保留客户、项目、任务、跟进 CRUD、项目进度联动、关联导航、业务总览和待办中心。

## 5. 技术边界

- 新增纯函数模块 company-project-customer-overview.js，独立计算项目/客户汇总。
- 新增 scripts/validate-v10.53.mjs，覆盖项目状态、进度平均、逾期项目、任务完成、客户/跟进关联及空数据。
- 沿用 public.company_records、现有认证和生产 company-api v5。
- 不新增数据库表/字段，不修改 migration、RLS、Edge Function、账号认证或生产业务数据。
- 不改变现有业务记录格式和 planner 快照隔离。

## 6. 验收标准

1. 项目总数和五类状态分布与完整项目列表一致。
2. 平均进度只排除已取消项目，计算和四舍五入准确。
3. 逾期项目按浏览器本地日期及状态准确识别。
4. 项目列表显示正确客户、进度和任务完成数；点击能打开对应项目详情。
5. 客户列表正确统计项目数、进行中项目数和关联跟进数；点击能打开客户记录。
6. 近期活动覆盖项目、任务和跟进，按最近活动时间排序，点击打开正确记录。
7. API 失败/分页不完整与真正空数据区分处理。
8. 三语和桌面/移动端布局正常；2-A、2-B、CRUD、进度联动和跨模块导航不回归。
