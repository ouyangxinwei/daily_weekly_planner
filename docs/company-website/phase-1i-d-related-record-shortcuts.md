# 阶段 1-I-D：关联记录快捷打开与编辑

- 应用版本：V10.49.0
- 开发分支：`feat/company-related-record-shortcuts-1i-d`
- 基线分支：`main`（V10.48.0）
- 数据库：沿用 `public.company_records`
- API：沿用生产 `company-api` v5

## 1. 发现的问题

阶段 1-I-B 已在客户卡片和项目详情展示关联记录预览，阶段 1-I-A/C 已提供跨模块导航和关联筛选。但预览中的记录名称只是静态文本，用户仍需进入列表并查找对应记录，才能编辑。

## 2. 本阶段实现

- 客户卡片的关联项目、任务、跟进预览改为可点击入口。
- 项目详情中的关联任务和跟进预览改为可点击入口。
- 点击预览记录后，切换到对应业务模块并直接打开该记录的编辑窗口。
- 保留记录原有客户/项目关系；打开任务编辑时确保所属项目选项仍可用。
- 从项目详情预览打开编辑器时先关闭详情对话框，避免模态对话框叠加。
- 为预览入口提供键盘焦点样式、语义化按钮和中英日文案兼容。
- 保留原有 CRUD、列表导航、筛选、分页及项目进度联动。

## 3. 数据与兼容性边界

- 不新增或修改数据库表、字段、索引、迁移和 RLS。
- 不修改 Edge Function；继续使用生产 `company-api` v5。
- 不修改账号认证、业务记录结构或云同步。
- 不写入或批量修改生产业务数据；打开编辑器本身不保存数据。

## 4. 验证范围

- JavaScript 语法检查覆盖公司业务脚本、客户工作区脚本和相关 E2E 测试。
- Playwright mock API 用例覆盖客户卡片项目/任务/跟进预览，以及项目详情任务/跟进预览的直接编辑入口，并验证客户/项目关联字段预填。
- 按用户既定偏好，不把 Playwright 浏览器安装或完整 E2E 执行作为合并前提；以语法/静态验证及部署后用户真实浏览器验收为准。
