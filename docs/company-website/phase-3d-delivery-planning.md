# Phase 3-D：项目交付与资源规划

## 目标
在现有客户、项目、任务、进度和活动历史基础上建立项目交付管理视图。优先纯前端分析，避免初期数据库/API 变更。

## 范围
- 3-D-A：计划/实际进度偏差。当前数据只有项目进度值和项目/任务状态，缺少历史计划基线与按日期保存的计划进度曲线。首版应明确标示“进度基线不足”，以任务截止日期、任务完成状态和项目手动/自动进度为可用指标，不伪造计划进度。
- 3-D-B：延期风险。基于项目目标日期、未完成/逾期/阻塞任务、任务日期覆盖情况与项目状态构建透明规则，展示风险因素与证据，不使用黑箱预测。
- 3-D-C：交付承诺。项目目标交付日期与客户承诺日期须分开；客户承诺日期目前不存在专用字段。兼容性首选项目 data 中的可选字段，待确认字段设计后再添加编辑 UI；不把 due_date 默认为客户承诺。
- 3-D-D：资源与工作量。当前任务记录未建立稳定的人员、估算工时和实际工时字段。建议可选 data.assignee、data.estimated_hours、data.actual_hours，空值视为未知，绝不视为零。第一阶段只支持汇总/分布，不做人员绩效评价。

## 实施原则
1. 复用 company_records 和现有完整分页读取缓存。
2. 首版不改变数据库、RLS、Edge Function、认证或生产数据。
3. 纯分析规则模块化、可独立测试，输入既有记录并输出报告。
4. 仅依据明确的日期/状态/估算规则，解释每项风险来源。
5. 任务依赖关系需有可维护的依赖数据结构；当前未有依赖关系字段，不以项目内任务排序暗示依赖。后续采用 task data.dependencies（任务 ID 数组），并检测无效链接和循环。
6. 三语支持，避免将分析称作 AI 预测。

## 交付建议
- 3-D-A/B 合并为首个切片：项目交付风险分析台，包含项目状态/进度、期限风险分层、任务证据、进度数据完整性提示。
- 3-D-C 独立切片：客户承诺日期与交付差异。
- 3-D-D 独立切片：工作量、人员分配及依赖关系编辑与风险计算。
