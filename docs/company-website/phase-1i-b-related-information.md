# 阶段 1-I-B：关联信息展示优化

- 应用版本：V10.47.0
- 开发分支：`feat/company-related-information-1i-b`
- 基线提交：`e5091f6b99dd865273175bb1b38d01a6993cc554`
- 数据库：沿用 `public.company_records`
- API：沿用生产 `company-api` v5

## 1. 目标

在客户页面和项目详情中直接呈现已存在的关联业务信息，减少反复切换模块才能了解客户/项目全貌的操作。

## 2. 客户卡片

- 显示关联项目、任务、跟进记录的总数。
- 每类最多预览 3 条记录；项目显示进度（若有），任务显示状态，跟进显示日期。
- 完整记录继续通过原有「查看项目」「查看跟进」入口访问；任务预览按所属项目归集。
- 关联关系使用客户 ID、项目 ID、parent_record_id、related_record_ids 和既有 JSONB data 字段，不按名称猜测。

## 3. 项目详情

- 增加关联任务与跟进记录预览。
- 每类最多显示 6 条；任务显示状态、截止日期和说明，跟进显示日期、状态和结果。
- 保留原有「管理任务」「查看跟进」入口，用于查看和管理完整列表。

## 4. 数据与兼容性边界

- 不新增数据库表、字段、索引、迁移或 RLS 策略。
- 不修改 company-api v5、认证、客户/项目/任务/跟进 CRUD 和项目进度联动。
- 不改变既有业务记录；仅按现有关系读取和汇总。
- 关联预览读取失败时显示可理解的提示，不阻止客户资料和项目详情主体显示。
- 中英日文案和移动端布局同步维护。

## 5. 验证

- Playwright mock API 测试覆盖客户卡片关联项目/任务/跟进，以及项目详情任务/跟进预览。
- JavaScript 语法检查覆盖两个业务模块和相关 E2E 测试。
- 不向生产业务数据写入测试记录。

## 6. 最终交付状态

PR 合并、Pages 部署、自动化验证和用户真实浏览器验收状态将在最终交付时补齐。
