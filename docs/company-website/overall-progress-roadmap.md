## 3. 当前进度怎么理解

### 已经具备的主要能力

- 客户资料的新增、查看、编辑和删除。
- 项目管理及项目详情。
- 任务与项目关联、任务状态和截止日期管理。
- 业务跟进及客户/项目关联。
- 项目手动进度，以及按已完成任务比例自动计算的进度模式。
- 客户、项目、任务、跟进之间的跨模块导航。
- 客户卡片和项目详情中的关联记录预览。
- 关联筛选上下文提示、快捷清除。
- 从关联预览直接打开相应记录编辑窗口。

### 目前仍在改善的体验

当前分支正在为任务列表增加逾期、今日到期、未来 7 天和无截止日期筛选，并使其与现有搜索、状态和项目筛选组合使用。

该范围已获确认，目前正在功能分支实施，尚未合并或部署。

## 4. 下一步与剩余工作估算

### 当前明确的下一步

**1-I-E：任务截止日期快速筛选（开发中）**

已确认范围：
1. 逾期任务：截止日期早于今天且状态不是已完成。

约束：复用现有 `due_date` 和任务状态；不新增数据库字段，不修改表结构、迁移、RLS 或 `company-api`。

## 5. 每次重新开始时的接续规则

重新打开项目时，先读本文，再读对应阶段文档。按以下顺序继续：

1. 确认 GitHub 仓库 `ouyangxinwei/daily_weekly_planner` 的 `main` 最新提交和当前 Actions 状态。
2. 查看本文的“当前完成位置”和“下一步”。
3. 若 1-I-E 正在开发或已合并，先核对分支、PR 和 Actions 状态，再继续当前步骤。
4. 功能开发从最新 `main` 创建独立分支；不直接在 `main` 开发。
5. 沿用现有数据库和生产 `company-api` v5，除非用户明确批准架构变更。
6. 按必要范围做静态检查和针对性验证；不把 Playwright 浏览器安装或完整 E2E 作为默认合并前提。
7. PR squash merge 后检查 GitHub Actions 的 build 和 deploy。只有两者成功，才能报告 Pages 已部署。
8. 部署后由用户进行真实浏览器验收；收到“验收 OK”后更新阶段文档和本文状态。
9. 不把“代码已合并”“Pages 已部署”“用户已验收”混为同一个状态。
