# 阶段 1-F：项目详情与进度管理

- 应用版本：V10.43.0
- 开发分支：`feat/company-project-details-progress`
- Supabase 项目：慢慢计划现有项目 `kopvznygsqsheibsjjvv`
- 数据库迁移：无
- Edge Function：复用现有 `company-api` v3；无部署变更

## 1. 功能范围

### 项目详情
- 在项目列表中提供「查看详情」入口。
- 详情视图展示项目名称、所属客户、项目状态、开始日期、预计完成日期、项目说明和当前进度。
- 详情视图提供编辑入口，沿用现有项目编辑表单。

### 项目进度
- 进度由用户手动维护，范围为 0–100 的整数百分比。
- 项目列表卡片与详情视图均显示百分比和进度条。
- 新建项目默认进度为 0%。
- 旧项目缺少进度字段时兼容显示 0%，不要求数据迁移。
- 进度不根据任务数量自动计算；项目任务管理留在后续阶段 1-G。

## 2. 数据与 API

继续使用现有 `public.company_records` 项目记录：
- 进度保存到项目记录 JSONB：`data.progress_percent`。
- 更新继续调用 `PATCH /records/:id`。
- 不修改 `record_type`，不改变项目与客户的关联。
- 不新增数据库表、不修改 RLS/RPC、不修改 Edge Function 和认证机制。
- 公司业务数据仍与计划模块 LocalStorage、JSON 备份和云端快照隔离。

## 3. 界面与兼容

- 中文、英文、日文界面均提供项目详情和进度文案。
- 详情对话框适配桌面与移动端。
- 用户输入的项目说明通过 textContent 呈现，避免将业务内容作为 HTML 解析。
- 进度输入限制为 0–100 整数；非法值不提交。

## 4. 验证

新增/扩展 `tests/e2e/company-business.spec.js` mock API 测试：
- 新建项目时保存进度。
- 项目卡片显示进度。
- 详情视图显示客户、说明和进度。
- 编辑项目后更新进度。
- 验证请求仍使用现有 Basic Authorization，并通过通用 records API 操作。

自动化测试只使用模拟 API，不写入真实业务数据。真实账号下的进度保存仍需在 Pages 部署后由用户浏览器验证。
