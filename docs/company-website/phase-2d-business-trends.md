# 阶段 2-D：业务趋势与周期复盘

## 1. 目标

新增「业务趋势」工作区，基于现有客户公司业务记录，按周或月复盘项目新增/完成、任务新增/完成和客户跟进活动，帮助识别业务节奏变化。此阶段是 Phase 2 最后一个子阶段，不扩展到预测、收入分析、客户转化率或自动经营建议。

## 2. 周期与展示

- 周视图：最近 8 个自然周，周一至周日；当前周按截至今天的已发生记录展示。
- 月视图：最近 6 个自然月；当前月按截至今天的已发生记录展示。
- 默认月视图；切换周/月仅重新计算当前已加载数据，不重复请求 API。
- 顶部周期摘要：项目新增、项目完成、任务新增、任务完成、跟进记录数。每项同时显示相对上一周/上月的数量变化（绝对差值，不用百分比掩盖小样本）。
- 三组趋势图：项目新增 vs 完成、任务新增 vs 完成、客户跟进记录数。
- 图表显示每个周期的数量与标签；无数据周期显示 0，空数据和读取失败严格区分。
- 复盘提示只描述实际统计变化，例如较上一周期增加/减少/持平，不生成预测或未经数据支持的结论。

## 3. 数据口径（重要）

当前业务表没有专门的 completed_at / 状态变更事件日志，也没有历史进度快照，因此趋势必须明确标注可观测口径，不伪装为精确的历史状态变化：
- 新增项目：project.created_at 落在周期内。
- 项目完成：当前 status=completed，且 updated_at 落在周期内。此项代表“完成项目记录的最近更新时间”，是完成时间代理值；用户后续编辑已完成项目时可能改变归属周期。
- 新增任务：task.created_at 落在周期内。
- 任务完成：当前 status=completed，且 updated_at 落在周期内。此项同样是最近更新时间代理值，不等同于有审计记录的真实完成时间。
- 客户跟进：follow_up.record_date 优先，缺失时使用 created_at；统计跟进发生日期，不按 updated_at 重新归档。
- 不根据 due_date 推算完成，不将当前状态反推为过去每个周期的状态。
- 不显示历史活跃项目数、历史未完成任务数、历史项目进度变化等当前数据无法准确还原的指标。
- 图表日期按浏览器本地时区归属自然周/月；日期字段 YYYY-MM-DD 按其日历日期处理。

## 4. 数据读取与完整性

- 使用 company-api v5 GET /records 分页读取 project、task、follow_up。
- 每页 limit=100，连续读取全部页面，校验每页 total 一致、不能提前空页/短页结束，最终数量必须等于 total。
- 不使用当前列表第一页、前端缓存或 10,000 条截断结果作为统计全量。
- API 失败/分页不完整时显示错误并清空 KPI/趋势图，不显示为 0。
- 不新增汇总数据副本，不修改 Supabase 表、RLS、migration、Edge Function、认证或生产业务数据。

## 5. 交互与兼容

- 新增独立「业务趋势」导航入口，与业务总览、待办中心、项目与客户概况并列。
- 周/月切换；刷新按钮重新读取完整记录。
- 中、英、日三语；桌面/移动端自适应，图表可读且不依赖颜色单独传达含义。
- 保留 Phase 1 CRUD、项目进度联动、关联导航、任务截止日期筛选，以及 2-A/2-B/2-C 页面。
- 页面首次打开时读取数据；切换周期不重复请求。

## 6. 自动化验证

新增 company-business-trends.js 纯函数和 scripts/validate-v10.54.mjs，覆盖：
- 周一周界、跨年周、月边界、当前不完整周期。
- created_at、updated_at 完成代理、record_date 优先和 created_at fallback。
- 不将非 completed 项目/任务计入完成趋势。
- 8 周/6 月周期长度、空数据和日期无效数据。
- 当前周期与上一周期差值。
- 不把 updated_at 代理值表述为真实完成时间。

接入现有 GitHub Actions 语法检查和回归验证。

## 7. 验收标准

1. 周视图连续展示最近 8 个自然周，周一为起点；月视图展示最近 6 个自然月。
2. 项目/任务新增按 created_at 统计；完成趋势严格按当前 completed 状态 + updated_at 代理口径统计。
3. 跟进优先按 record_date 统计，缺失时回退 created_at。
4. KPI 和上一周期差值与图表汇总一致。
5. 零数据周期显示 0；API 失败或分页不完整显示错误而非 0。
6. 周/月切换无需重复 API 请求；刷新会重新读取完整数据。
7. 三语和桌面/移动端布局正常；Phase 1、2-A、2-B、2-C 无回归。
8. 完成时间代理值及历史快照限制在页面和文档中明确说明。
