# 阶段 1-I-A：公司业务工作区跨模块导航

- 应用版本：V10.46.0
- 开发分支：`feat/company-workspace-navigation-1i-a`
- 基线分支：`main`（`a2376aca0d0ece4e6376aceeac7f06272dacbd7d`）
- 数据库：沿用 `public.company_records`
- API：沿用生产 `company-api` v5；本阶段不修改 Edge Function 或数据库结构

## 1. 目标

让客户、项目、任务、跟进之间已有的业务关系能够直接导航，减少用户在不同工作区反复搜索和切换的成本。只使用现有记录 ID 和关联字段，不创建新的业务关系或复制业务数据。

## 2. 导航行为

| 当前页面 | 操作 | 目标 |
|---|---|---|
| 客户卡片 | 查看项目 | 项目列表按客户 ID 筛选 |
| 客户卡片 | 查看跟进 | 跟进列表按客户 ID 筛选 |
| 项目卡片 | 点击所属客户 | 定位并显示该客户资料 |
| 项目详情 | 查看客户 | 定位并显示所属客户 |
| 项目详情 | 管理任务 | 打开该项目的任务列表 |
| 项目详情 | 查看跟进 | 跟进列表按项目 ID 筛选 |
| 任务卡片 | 查看项目 | 打开所属项目详情 |
| 跟进卡片 | 查看客户 | 定位并显示关联客户 |
| 跟进卡片 | 查看项目 | 打开关联项目详情 |

客户、项目的跳转使用真实记录 ID；不通过名称猜测关联对象。客户详情定位通过现有 `GET /customers/{id}` API 读取目标记录。项目/跟进关系筛选跨越分页读取记录后再筛选，避免仅在当前页内查找。

## 3. 兼容性与边界

- 客户、项目、任务、跟进的 CRUD 行为保持不变。
- 项目手动/自动进度联动保持不变。
- 沿用当前账号认证和 `company-api` v5。
- 不新增数据库表、字段、迁移或 Edge Function。
- 找不到关联项目时保留原工作区，不伪造项目详情。
- 中、英、日三语导航文案齐全；移动端操作按钮允许换行。

## 4. 自动化验证

新增 `tests/e2e/company-navigation.spec.js`，使用 Playwright mock API 数据覆盖：
- 客户 → 项目、客户 → 跟进；
- 项目 → 客户、项目 → 任务、项目 → 跟进；
- 任务 → 项目详情；
- 跟进 → 客户、跟进 → 项目；
- 客户定位通过 ID 读取，而不是依赖客户名称搜索。

测试使用隔离的模拟数据，不访问或修改生产业务记录。
