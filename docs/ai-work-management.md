# AI 工作管理模块设计规范

- 文档状态：**设计定稿 v1.0；等待用户决定是否开发（2026-11-28）。仅完成文档，不代表功能已实现。**
- 所属项目：`ouyangxinwei/daily_weekly_planner`
- 产品定位：AI 工具资料库 + 人工工作调度
- 使用重点：桌面网页端优先；移动端保持基本可用
- 实施原则：沿用现有原生 HTML/CSS/JS、主题、多语言、数据管理及发布规范；不得擅自迁移框架

## 1. 目标与范围

建立一个集中管理个人常用 AI 工具、账号状态和 AI 辅助工作任务的模块。第一阶段不连接各 AI 服务的 API，不自动调用模型，也不自动替用户分配工具。模块提供资料维护、状态查看、人工推荐辅助、官网跳转、点击频率统计、工作任务和使用记录。

核心目标：

1. 集中维护 AI 工具及其一个或多个账号。
2. 手动维护账号类型、模型、可用状态、限流信息、恢复时间和优先级。
3. 根据工作任务需求与工具/账号资料提供候选推荐，由用户手动选择。
4. 点击工具简略名即可打开其官网，并累计点击次数。
5. 将「打开工具的点击统计」与「完成工作任务的使用记录」分开。
6. 本地缓存与云端保存并存，用户手动同步；提供完整 JSON 导入和导出。

明确不在第一阶段范围内：

- 不调用 ChatGPT、Claude 等服务的 API。
- 不自动识别或检测官方限流、账号余额、配额或模型状态。
- 不自动判断恢复时间到达后账号一定恢复。
- 不自动分配任务或自动启动 AI 工作流。
- 不要求用户为了使用本模块而在手机上安装或打开 AI App。

## 3. 信息架构与页面

模块包含四个主要页面/区域：

### 3.1 AI 总览

桌面端以紧凑列表/表格为主，不采用一张一张的大型卡片作为主要布局。AI 工具名称缩写是最主要的操作入口：点击名称打开对应官网，并累计一次入口点击。

总览列表字段：

| 列 | 内容 |
|---|---|
| AI 名称缩写 | 必须显示；可点击打开官网 |
| 主要功能 | 必须显示，例如日文修改、代码开发 |
| 语音支持 | 显示是/否；尚未确认时可显示待确认 |
| 用户名/账号 | 显示该工具下的账号用户名；多个账号可分行或紧凑展示 |
| 备注 | 默认直接显示，不要求额外点击展开；较长内容可换行或在不丢失内容的前提下适度折叠 |
| 点击次数 | 工具官网入口累计点击次数 |
| 操作 | 编辑工具、管理账号、隐藏等 |

分类、账号状态、最近点击时间可作为筛选条件、辅助信息或可配置列，不应挤占上述六项核心资料的可见性。**限流时间不作为总览主列表的常驻列**，在具体账号资料中维护和查看。

提供关键词搜索、分类筛选、账号状态筛选、点击次数排序、最近点击排序。总览顶部显示工具总数、账号总数、可用账号数、限流账号数等摘要。一个工具可有多个账号，因此账号相关信息必须按账号逐条管理，工具层面的状态只能作为汇总提示。

AI 资源库详情页负责展示完整工具资料和账号列表；总览不应把工具与账号误做成一对一关系。

### 3.2 AI 资源库

维护 AI 工具资料及其账号。

工具资料字段：

- 稳定 ID。
- AI 简略名（必填，列表展示名称）。
- 完整名称（可选）。
- 官网 URL（必填，工具级入口）。
- 主要功能（文本，用户自由维护，例如日文修改、代码开发）。
- 分类（支持维护）。
- 语音支持（是/否；若资料尚未核实，可暂存为待确认，但正式用户字段为是/否）。
- 工具备注（多行文本，自由维护；在总览列表默认显示）。
- 是否显示：显示、隐藏。
- 创建时间、更新时间。
- 点击次数、最近点击时间（统计字段，不由用户随意编辑）。

账号资料字段：

- 稳定 ID。
- 所属工具 ID（必填）。
- 用户名或账号标识（由用户手动填写；不要求密码）。
- 账号类型：免费、付费、企业、试用或自定义。
- 使用模型名称（可维护，允许多个模型或文本说明）。
- 当前状态：可用、限流、停用、待确认。
- 限流时间/预计恢复时间（日期时间，用户手动填写，可为空；记录限流解除或预计恢复时间）。
- 限流说明。
- 使用优先级（用户维护的排序值/高、中、低）。
- 账号备注（多行文本，自由维护；在账号详情/账号列表默认显示）。
- 创建时间、更新时间。

官网 URL、AI 名称缩写、主要功能、语音支持和工具备注属于工具；用户名、模型、账号类型、限流时间和账号备注属于账号。一个工具可以拥有多个账号。不得在普通本地持久化或 JSON 导出中保存密码、访问 Token、API Key 等认证秘密。

### 3.3 工作调度

用户创建工作任务并填写目标、说明、任务分类/所需能力、优先级和可选截止时间。

系统按以下信息形成候选推荐：

- 任务分类和所需能力与 AI 工具主要功能/分类的匹配程度。
- 账号当前状态。
- 账号使用优先级。
- 用户维护的模型信息。
- 工具是否显示/可用。

推荐结果只提供排序和理由，例如「功能匹配」「账号可用」「优先级较高」。用户必须手动选择工具和具体账号；系统不得自动分配或自动跳转。用户确认后可点击工具官网入口打开服务。

工作任务字段建议：

- 稳定 ID、标题、任务说明。
- 任务分类/所需能力。
- 优先级、状态（待处理、进行中、已完成、已取消）。
- 用户选择的工具 ID、账号 ID（允许未选择）。
- 创建/更新时间、开始/完成时间。
- 结果摘要和备注。

任务与账号关联时，账号必须属于所选工具。若任务尚未指定账号，不得伪造实际使用记录。

### 3.4 使用记录

使用记录用于追踪实际工作任务执行，而不是记录单纯的官网点击。

每条使用记录建议关联：

- 工作任务 ID。
- 实际使用的 AI 工具 ID。
- 实际使用的账号 ID（如能确定）。
- 开始时间、完成时间。
- 执行结果/备注。
- 创建时间。

一项任务可有多条使用记录，以支持同一任务先后使用不同 AI 工具或账号。记录必须保留当时使用的工具和账号关联；工具或账号被隐藏时，历史记录仍可查看。删除被历史记录引用的工具/账号时，应采用保护、停用或软删除策略，不得无提示级联清除历史。

## 4. 官网点击统计

点击统计是独立于工作任务使用记录的轻量行为统计。

规则：

1. 用户点击列表中的 AI 简略名/官网链接时，记为一次「工具入口点击」。
2. 每次用户主动点击计数加 1，并更新最近点击时间。
3. 统计按 AI 工具聚合，不按账号聚合；打开工具官网不意味着已选择或使用某个账号。
4. 点击次数用于查看日常使用频率和排行，可按次数降序排序。
5. 点击次数不等于实际使用次数、任务完成次数或模型调用次数；界面和统计不得将它们混称。
6. 不自动探测用户是否已登录、是否成功完成 AI 对话，也不采集 AI 网站内部活动。
7. 计数事件应与工具 ID 关联，支持数据导出、导入和跨设备同步。若保存逐次事件，使用唯一事件 ID 防止同一份事件在重复导入时被重复累计；汇总计数可由事件集合计算或在维护一致性的前提下缓存。
8. 只记录实现统计所必需的工具 ID 和点击时间；不记录用户在目标 AI 网站中的提示词、对话或页面内容。

若浏览器阻止新窗口或目标站点无法打开，点击行为仍可作为入口点击记录；该指标表示用户点击了入口，而不是确认外部页面成功加载。

## 5. 限流与账号状态

- 所有限流状态均由用户手动维护，不自动读取服务官方限额。
- 恢复日期时间由用户手动输入，允许为空。
- 当当前时间达到或超过填写的恢复时间，界面只提示「预计已恢复，请确认」，不得自动把账号状态改成可用。
- 用户确认后才可将状态改为可用；若仍不可用，用户可继续更新限流状态和恢复时间。
- 多账号工具的总览状态应显示各账号情况，避免单个账号限流导致整个工具被误判不可用。
- 「待确认」与「停用」必须与「限流」区分。

## 6. 数据模型建议

第一版逻辑实体：

| 实体 | 主要职责 | 关键关系 |
|---|---|---|
| ai_tools | AI 工具基本资料及入口统计 | 一个工具拥有多个账号、可被多个任务和使用记录引用 |
| ai_accounts | 工具下的账号、模型和限流状态 | N:1 关联 ai_tools |
| ai_categories | 可维护的工具分类（可采用独立表或受控分类数据） | 工具可关联分类 |
| ai_work_tasks | 用户创建的工作任务 | 可关联所选工具/账号 |
| ai_usage_logs | 实际任务执行记录 | 关联任务、工具和账号 |
| ai_tool_click_events | 官网入口点击事件 | 关联工具；事件 ID 唯一 |

关系概览：

```
ai_categories
     │
     └── ai_tools (1) ────── (N) ai_accounts
             │  │                  │
             │  ├──────────────┐   │
             │  │              │   │
             ▼  ▼              ▼   ▼
       ai_tool_click_events  ai_work_tasks
                                  │
                                  ▼
                             ai_usage_logs
                              ▲       ▲
                              │       │
                         ai_tools  ai_accounts
```

关系约束：

- 一个账号必须属于一个工具；删除工具前必须处理其账号及引用。
- 一个工具可以有多个账号。
- 任务选择的账号必须属于任务所选工具。
- 使用记录的账号必须属于该记录的工具；允许账号为空的记录应明确表示无法确定实际账号。
- 点击事件只关联工具，不要求关联账号或工作任务。
- 分类数据类型和引用方式应统一，不把分类 ID 与任意文本数组混用。
- 以上是逻辑数据模型，不代表已创建数据库表或 migration；具体主键、索引、约束和 API 在实施阶段再按现有项目规范确定。

## 7. 本地缓存、云端保存、手动同步与 JSON

### 7.1 总体原则

采用「本地缓存 + 云端保存 + 用户手动同步 + JSON 导入/导出」。AI 工作管理数据必须有独立的数据分区，不得混入 Plan、Work、Foreign Language、Organize、Results、Future、Memo、公司业务数据、仓库管理数据、运行日志或天气缓存。

本地数据用于日常快速访问；云端用于跨设备保存和恢复。用户不需要每次编辑都立即联网，也不要求自动实时同步。

### 7.2 手动同步

- 提供明确的「上传到云端」和「从云端下载」操作。
- 上传前/下载前展示本地与云端更新时间、数据范围和覆盖影响，并要求用户确认。
- 上传仅替换 AI 工作管理自己的云端数据分区；不得覆盖其他模块。
- 下载仅替换本机 AI 工作管理数据；不得改动其他本地模块。
- 同步应检查确认期间云端数据是否发生变化；如检测到变化，应停止覆盖并要求重新检查。
- 只有云端写入或本地提交确实成功后才更新界面状态和同步时间。
- 网络失败、认证失败、校验失败或本地写入失败时，保留原有可用数据并明确提示。
- 第一版采用明确的快照上传/下载语义，不声称自动双向合并。多设备分别离线修改后，上传/下载可能覆盖另一端较新的变更；必须在确认界面说明。
- 本地缓存和云端分区均应有独立版本/更新时间元数据，避免误判同步状态。

### 7.3 JSON 导入与导出

- 导出完整 AI 工作管理数据，包含 schema 类型、版本、导出时间、工具、账号、分类、任务、使用记录、点击事件及必要的同步无关元数据。
- 不导出登录凭据、密码、Token、API Key 或其他认证秘密。
- 导入先校验文件类型、schema 版本、字段类型、必填字段、ID、引用完整性和重复事件 ID。
- 导入前展示新增、更新、跳过/冲突数量及可能影响；用户确认后才写入。
- 导入失败或取消时，原有本地数据必须保持不变。
- 导入合并策略与全量替换必须明确区分；默认不静默删除文件中不存在的本地记录。
- 导出文件应可用于备份和迁移；导入同一份含点击事件 ID 的文件不得重复累计点击次数。
- 旧版本数据升级应有 schema 版本和迁移策略。

## 8. 界面与多语言

- 桌面网页端为主要设计目标，使用密集、可扫描的列表/表格、筛选和排序。
- 手机端保留基本可操作性，允许横向滚动或调整列显示；不以手机卡片为主导重新设计整套交互。
- 复用慢慢计划现有深色/浅色主题、简体中文/日文/英文语言机制。
- 用户填写的工具说明、用户名、模型名和备注属于用户内容，不随界面语言切换自动翻译。
- 所有状态、按钮、确认提示、空状态和错误信息应纳入三语文案维护。
- 外部官网在新标签页打开；链接应清楚显示目标工具，不将用户输入内容拼接进 URL。

## 9. 与现有模块的边界

- AI 工作管理是独立工作区，不把 AI 账号混入慢慢计划登录账号或公司客户账号。
- 不修改现有 Work 工作事项的既有含义；AI 工作任务属于本模块内部任务，是否与 Work 模块建立入口或引用关系留到后续整合阶段确认。
- 不纳入计划工作区现有四模块快照，除非未来另行批准改变备份范围。
- 不影响外语学习、整理、成绩、未来、备忘、公司网站、GitHub 仓库管理和运行日志。
- 保持当前原生 HTML/CSS/JS 架构，不擅自迁移框架。
- 版本号、版本声明文件、三语 CHANGELOG、文档索引、测试和部署验证遵循仓库当前规范。
- 当前日常维护以 main 为基线；本设计不要求维护 development 分支。

## 10. 分阶段实施计划（尚未开始）

| 阶段 | 范围 | 完成标准 |
|---|---|---|
| Phase 1 | AI 资源库、工具列表、账号维护、初始 10 个工具 | 工具/账号 CRUD、列表显示、官网跳转和基础数据持久化 |
| Phase 2 | 状态与限流管理、搜索筛选排序、点击统计与排行 | 手动限流恢复、预计恢复提示、点击事件去重和排行 |
| Phase 3 | 工作任务、能力匹配推荐、人工选择和官网跳转 | 推荐有理由但不自动分配，任务可记录所选工具/账号 |
| Phase 4 | 使用记录和统计 | 任务执行记录与点击统计分离，关联关系正确 |
| Phase 5 | 与现有 Work 模块整合评估 | 先确认入口/引用方式，不破坏既有 Work 数据和行为 |

阶段可按依赖调整，但不得跳过数据备份、失败保护、权限和数据隔离设计。

## 11. 验收清单

- 10 个初始工具名称正确，URL 可维护；不纳入 Chat — モカ 和 DeepSeek Harness。
- 总览列表默认可见 AI 名称缩写、主要功能、语音支持、用户名/账号、备注和点击次数；备注无需额外点击才能查看。
- 限流时间以日期时间字段保存在账号资料中，不作为总览主列表的常驻列。
- 一个工具可创建多个账号；工具 URL 与账号用户名/限流字段归属正确。
- 工具列表为桌面端优先的列表/表格；搜索、筛选、排序可用。
- 点击工具入口一次，点击次数只增加一次；重复导入同一点击事件不会重复计数。
- 点击次数排行与最近点击时间正确；不把点击次数当成任务完成数。
- 限流恢复时间到达只显示「预计已恢复，请确认」，不自动恢复状态。
- 推荐依据可解释，用户最终手动选择工具和账号。
- 任务与使用记录关联正确；删除/隐藏工具或账号不破坏历史记录。
- 本地刷新后数据保留；手动上传/下载只影响 AI 工作管理数据。
- 同步覆盖前有时间检查、影响说明和确认；网络/认证/存储失败不丢失原数据。
- JSON 导入校验、预览、取消和失败保护正确；导出可重新导入。
- 三语、深浅主题和桌面/移动端基本可用。
- 与其他模块的数据、存储和备份范围完全隔离。
- 测试、真实浏览器验收和线上部署分别记录；没有部署证据不得宣称已部署。
