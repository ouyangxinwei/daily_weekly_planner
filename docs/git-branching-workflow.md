# Git 分支管理规范

> 本文是本仓库唯一权威的分支工作约定。日常开发固定使用 \`development\`，正式稳定版本固定使用 \`main\`，Agent 实验分支单独保留。

## 1. 长期保留的分支

| 分支 | 用途 | 生命周期 | 操作规则 |
|---|---|---|---|
| \`main\` | 稳定版本与 GitHub Pages 正式部署 | 永久 | 仅接收经过验证并获得仓库所有者明确许可的 \`development\` 集成 |
| \`development\` | 所有日常功能、修复、文档和版本维护 | 永久 | 默认开发分支；直接在此分支持续完成开发和验证 |
| \`feat/agent-plan-steps\` | Agent 工作流实验及历史执行证据 | 特别保留 | 独立隔离，不参与日常开发和常规清理；删除必须先获得所有者明确许可 |

除上述三个分支外，默认不创建或长期保留其他分支。当前远程分支结构已整理为以上三个分支。

## 2. 日常开发流程

1. 开始工作前检查远程分支和工作区状态，确认在最新 \`development\` 上。
2. 所有新功能、缺陷修复、重构和文档更新默认直接在 \`development\` 完成，不为每个小功能单独创建分支。
3. 以小步提交方式推进；不覆盖或重置他人已提交的工作。
4. 开发中遇到暂时无法解决的问题，先标注为 **「未完成」**，记录现象、原因、影响范围和下一步处理建议。只要不影响其他独立任务，就继续推进其他工作。
5. 每个阶段同步维护相关文档，包括 README、项目总览、产品规范、功能说明、技术手册、开发历史、三语版本记录和当前交接文档。仅更新与本次变化相关的文档，不为形式而重复复制内容。
6. 按风险执行必要的静态检查、验证脚本、单元测试或构建。明确区分通过、失败、跳过和未执行。
7. 阶段完成后向仓库所有者报告：修改内容、涉及文件、提交、验证结果、未完成事项及后续建议。

## 3. 从 development 集成到 main

**合并到 \`main\` 必须先获得仓库所有者对本次集成的明确许可。**

获得许可后：

1. 再次确认 \`development\` 与 \`main\` 的差异、目标提交、冲突和验证结果。
2. 使用仓库允许的正常合并方式将 \`development\` 集成到 \`main\`；如保护规则要求 PR，则创建目标为 \`main\` 的 PR。
3. 不使用强制推送、公共分支重置或绕过保护规则的方式集成。
4. 合并后确认 \`main\` 已包含预期提交。
5. 检查对应 GitHub Actions 与 GitHub Pages 部署记录。只有目标 \`main\` 提交对应的 Pages 构建和部署均成功，才可报告已部署。
6. 部署失败或仍在运行时，明确报告状态，不得将其描述为已上线。

没有明确许可时，工作停留在 \`development\`；不得因为 PR 已创建、测试通过或助手判断风险较低而自行合并。

## 4. Agent 分支例外

- \`feat/agent-plan-steps\` 是仓库所有者明确要求保留的 Agent 工作流实验分支。
- 该分支不属于日常功能开发分支，不应自动合并进 \`development\` 或 \`main\`。
- Agent 实验脚本可按其专项指南在该分支执行；任何将其成果纳入正式产品的操作，必须单独审查并取得所有者明确指示。
- 不得将其纳入普通临时分支清理。

## 5. 临时分支例外

仅当技术限制、外部协作或隔离验证确实无法在 \`development\` 上安全完成时，才考虑创建短期分支。应先说明必要性和回收方式；不得因习惯、每个功能或每次文档修改而创建分支。未经许可不得创建新的长期分支。

## 6. 「未完成」事项记录规范

发现暂时无法解决的问题时，使用 \`未完成\` 状态或特殊标记，并记录：

- **现象：** 当前发生了什么，如何复现。
- **原因：** 已确认原因；尚未确认时写明「原因待查」，不得猜测。
- **影响：** 影响的功能、数据或用户流程。
- **下一步：** 后续检查/修复动作及必要依赖。
- **是否阻塞：** 若不影响其他独立工作，应继续推进并保留此记录。

未完成事项不能被写成已完成，也不能因暂时搁置而从文档中悄悄删除。

## 7. 每阶段交付检查清单

- [ ] 工作始终在 \`development\`，没有误改 \`main\`。
- [ ] 新功能、修复和文档变更已完成或明确标记未完成。
- [ ] 相关 README、产品/功能/技术文档、开发历史、版本记录和交接文档已更新。
- [ ] 已运行与本次变更风险相匹配的验证，并如实记录结果。
- [ ] 已向仓库所有者报告变更、测试结果和未完成事项。
- [ ] 未经明确许可，没有合并到 \`main\`。
- [ ] Agent 保护分支未被修改或删除。

---

**默认原则：日常只在 \`development\` 开发；\`main\` 只接收经所有者明确许可的稳定成果；\`feat/agent-plan-steps\` 独立保留。**
