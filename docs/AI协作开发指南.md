# AI 协作开发指南

本文件记录计划网页的项目背景和迭代约定，供后续协作时作为产品资料。每次修改优先围绕一个目标，保持数据安全和已有功能。

## 1. 项目背景

这是一个原创的轻量个人计划网页，使用原生 HTML、CSS 和 JavaScript。主要文件为 `index.html`、`manifest.webmanifest`、`sw.js` 和 `icon.svg`。产品支持每日、每周、每月、每年计划，新增、编辑、删除、完成跟踪和浏览器本地存储，不含账号或后端。

## 2. 推荐需求格式

```text
目标：
当前表现或问题：
期望结果：
不可破坏的功能：
验收标准：
请说明修改文件、数据影响、验证方式，以及 Service Worker 缓存名是否需要升级。
```

## 3. 协作约定

- 尽量小范围修改，避免无关重写。
- 不要把用户输入作为 HTML 插入页面；应以文本方式显示。
- 修改本地数据结构时考虑已有用户数据的兼容迁移。
- 保持 JSON 备份导入校验与本地存储 schema 同步；任何格式错误不得覆盖当前数据。
- 备份导入采用整份替换；如新增合并模式，应明确展示冲突处理规则。
- 分类选项、旧数据默认类别和筛选／进度统计行为变化时，同步维护玩法说明、技术手册和 JSON 兼容逻辑。
- 修改星级优先级时保留 1–3 的数据边界、旧记录默认 1 星、SVG 图标显示和备份兼容行为。
- 临时计划仅在创建所在自然日／周／月内有效；调整周期标识或过期清理时同步检查备份恢复、完成记录清理及每周周一边界。
- “随机”视图是用户临时安排的独立清单，不代表系统随机抽取任务；保留与普通计划一致的编辑和追踪能力。
- 批量清理只能作用于当前选中周期；增加批量删除时须保留确认步骤，并清除关联完成记录。
- 修改页面功能后同步更新 `玩法与系统说明.md`、`技术手册.md` 和 `CHANGELOG.md`。
- 修改静态资源后更新 Service Worker 缓存名，避免线上客户端继续使用旧缓存。
- 说明功能是否需要 HTTPS、真实手机或浏览器手动确认。
- 不要声称已验证未实际检查的浏览器或设备行为。

- 修改提醒逻辑时保留本地时间语义、一次性通知、防重复标记和未完成计划过滤；明确页面关闭时不具备后台触发能力。

## 4. 后续功能提示模板

```text
请基于当前慢慢计划网页的现有实现完成一个小目标。
先说明涉及文件和数据影响，再修改。
保留每日、每周、每月、每年视图、计划编辑与完成状态、本地存储。
避免引入服务端或第三方依赖，除非需求明确要求。
完成后列出改动、验证结果、已知限制，并同步相关文档和版本记录。
```
